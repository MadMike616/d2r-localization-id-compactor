1.6.1
- Use Y/YES or N/NO for the final confirmation in all four workflows and
  advanced repairs, ignoring letter case and surrounding whitespace.
- Keep no default: blank or invalid answers ask again; end of input cancels.
- Keep the operation's JSON/save-edit scope visible in its final prompt.

1.6.0
- Add option 4, EDIT SAVE FILES ONLY. Read current item-runes.json and migrate
  runewords in all direct character/shared-stash saves without changing JSON.
- Automatically identify old IDs by exact string key from the mod's backed-up
  mappings and item-runes snapshots, including several earlier compactions.
- Support mixed old/current saves, include Chronicle runeword history, and keep
  item properties and saved drop-source IDs unchanged.
- Verify all selected save backups plus the current rune table, history inputs,
  parsing tables and detected metadata before editing any save.
- Reject unknown, removed or conflicting runeword identities rather than guess;
  stop the entire batch for unsupported save layouts or parsing failures.
- Keep all four choices explicit with no default; accept numbers or names in
  any letter case. Add --history-folder for backups stored elsewhere.
- Document exactly what option 4 overwrites, its history requirements, and how
  to restore its original save backups without replacing localization JSON.

1.5.0
- Replace the main menu with three explicit choices and no default:
  STANDARD COMP, SKIP RUNEWORDS, and COMPACT AND EDIT SAVES.
- Keep options 1 and 2 JSON-only; option 2 preserves item-runes.json and its
  1000-ID buffers for existing saves.
- Add combined compaction/save migration with detected mod paths and a mapping
  generated by the same operation; no mapping CSV selection is needed.
- Migrate runeword items in characters/stashes, Chronicle runeword history,
  and known saved Chronicle drop-source localization IDs.
- Validate the whole batch, verify all JSON/save backups before editing,
  and recover both groups if replacement fails. Include a joint restore guide.
- Reject ambiguous IDs, unsupported saves and pre-existing stale runeword IDs
  rather than guessing. Keep advanced historical repair commands available.
- Clearly document that option 3 overwrites save files and describe its scope.

1.4.0

  Saved Games location, including redirected folders and custom savepath names.
- Offer numbered save selection in repair menus and a detected folder default;
  also detect complete mod-table folders and safe mod-local backup defaults.
- Add --mod-folder, --auto-saves and read-only --detect-paths options.
- Keep manual overrides for unknown layouts and require explicit scope when
  several shared-stash files exist. ID mapping selection remains explicit.
- Back up detected mod metadata and abort if it changes after selection.
- Reject item-repair backup destinations inside the mod-table/game-data tree.

1.3.1

  and widths, making mismatched historical save/table layouts easier to identify.

  before editing; the utility never guesses widths or migrates unrelated stats.

1.3.0
- Add optional runeword item ID repair for selected character and shared-stash
  saves using the old-to-new mapping and the mod's effective game-data tables.
- Inspect player equipment, inventory, cube, personal stash, cursor, corpse,
  mercenary and iron-golem items, plus normal and advanced shared-stash tabs.
- Patch only saved runeword ID bits and necessary character checksums;
  optionally include Chronicle history in the same repair operation.
- Validate and back up all selected saves before editing any; retain the
  mapping, mod tables, hashes, detailed report and restore instructions.
- Require REPAIR ITEMS confirmation, provide a preview, and attempt batch
  rollback on write failure. Clearly document save-editing scope and limits.
- Bundle the runtime in one portable Windows x64 EXE and include third-party
  licenses in the package and through --licenses.
